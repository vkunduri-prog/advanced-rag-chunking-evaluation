# Project Explanation

The project addressed a central problem in Retrieval-Augmented Generation: a language model cannot generate a well-grounded answer when the retrieval system supplies fragmented or context-poor evidence. Traditional fixed-size chunking is easy to implement, but it may separate statements from the surrounding information needed to interpret them. Our team built a RAG comparison framework to study how regular chunking, contextual retrieval, late chunking, and meta-chunking affect retrieval relevance, response quality, processing time, and memory usage.

The broader system used Python and Streamlit for the application workflow, FAISS for similarity search, and RocksDB for persistent storage of chunk content and metadata. The team initially tested Qwen as a generation backend, but it was too slow in the available environment, with individual responses taking up to approximately twenty minutes. A faster API-based language model was therefore used for the interactive answer-generation path. The system displayed outputs from the different chunking methods in one interface so their behavior and resource trade-offs could be compared.

My main responsibility was contextual retrieval. I prepared the text corpus using sentence tokenization and punctuation-aware segmentation, then integrated Llama-3.2-1B-Instruct to generate a concise contextual description for each chunk. I appended that description to the original chunk before indexing, giving the retriever both the source passage and a higher-level explanation of its role in the document. I also tested whether the enriched chunks remained aligned with the source and supported more relevant retrieval.

One important challenge was ensuring that generated context improved retrieval without replacing or distorting the original evidence. The design preserved the source passage and treated the generated description as supplemental retrieval metadata. Another project-level challenge was comparing strategies that perform different amounts of work during ingestion and query processing. The team collected exploratory timing and memory measurements, but the final report did not include enough raw benchmark detail to establish one universally superior method.

The project showed me that RAG quality depends heavily on upstream information architecture. Chunk size, logical boundaries, contextual enrichment, persistence, and evaluation design all influence the evidence eventually presented to an LLM. A production continuation would use a labeled retrieval benchmark, standard metrics such as Recall@k and nDCG, groundedness evaluation, and adaptive routing that selects a chunking strategy according to the document and query.
